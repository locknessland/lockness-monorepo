# Testing & CI audit — 2026-09-04

Read-only audit of the Lockness testing and CI system, with a phased,
backlog-ready improvement plan. Scope: `.github/workflows/`, `deno.jsonc` tasks,
`docs/testing.md`, git hooks, and a per-package sampling of test quality across
all 28 workspace members.

---

## Current-state summary

**Verdict: uneven.** The framework has genuinely strong tests where it matters
most (session, core, validator, logger) with a clear, documented discipline —
FakeTime, in-memory mocks, hermetic and fast. But that discipline is not
enforced or measured: CI runs **only on pull requests**, there is **no coverage
measurement or gate**, the data layer (`drizzle`) is **entirely untested**, and
CI runs on a **single OS with a floating Deno version**. The result is a suite
that is good by convention and fragile by process — a direct push to `main` (the
documented, PR-optional workflow) ships with zero server-side checks.

Measured totals: **184 test files** across `packages/` (both `*.test.ts` and
`*_test.ts` naming conventions in use); `app/` has **0** tests.

### CI / gate topology

- **`test.yml`** triggers on `pull_request` to `main`/`develop` **only** — no
  `push` trigger. Steps: lint, `deno check`, `fmt --check`, `deps:analyze`,
  `agents:brief --check`, `publish:check`, `deno task test`, plus a separate
  `kits` job (`kits:smoke`).
- **`publish.yml`** triggers on GitHub release; re-runs the gate +
  `publish:check --registry` then `deno publish`.
- Runner: `ubuntu-latest`, `deno-version: v2.x` (floating). **No OS matrix, no
  Deno-version matrix, no coverage step.**
- **Local hooks** (opt-in via `deno task hooks:install`): `pre-commit` (check +
  lint --fix
  - fmt on staged, re-stages), `pre-push` (fmt, lint, check, deps:analyze,
    agents:brief, test). Hooks are bypassable (`--no-verify`) and absent on a
    fresh clone or in CI.
- `deno.jsonc` defines `test:coverage` (`deno test --coverage` →
  `deno coverage --lcov`) that **nothing in CI invokes**. It also only covers
  `packages/`, not `app/`.

### Test-quality patterns observed

- **Strong exemplar:** `packages/session/tests/wire_format.test.ts` documents
  the threat model in-test and asserts security invariants (`assertRejects`, GCM
  tag, per-cookie salt).
- **Shared helpers:** only `packages/storage/tests/support/mock_driver.ts`
  exists as a reusable in-memory fake. No monorepo-wide test-support package.
- **HTTP testing:** 18 files drive the app via Hono's `app.request(...)` /
  `app.fetch(...)`; each hand-rolls setup — no shared HTTP test-client helper.
- **FakeTime:** promoted heavily in `docs/testing.md` but used in only **9**
  files.
- **Mocking:** **zero** use of `@std/testing/mock` (spies/stubs) — all doubles
  hand-rolled.
- **Sanitizers:** `sanitizeResources`/`sanitizeOps` are explicitly **disabled**
  in `core/tests/kernel.test.ts` and `storage/tests/cloud.test.ts` — masks real
  leaks.
- **Naming drift:** `vite`, `markdown`, `container` use `_test.ts`; everyone
  else uses `.test.ts`. `docs/testing.md` mandates `.test.ts`.

## Findings (ranked by severity)

### HIGH

**F1 — CI runs only on pull_request; direct pushes bypass all server-side
checks.** `test.yml` has no `push` trigger. The project's commit discipline
(hard rule #9) permits committing straight to a branch, and releases publish
from `main`. A push to `main`/`develop` that did not arrive via PR runs **zero**
CI. The only push-time gate is a local, opt-in, `--no-verify`-bypassable git
hook. This is the single largest process gap.

**F2 — No coverage measurement or gate anywhere in CI.** The `test:coverage`
task exists but is never run in CI. There is no coverage number, no per-package
floor, no ratchet, no regression signal. Coverage can silently rot and no gate
notices — directly undercuts the pre-completion gate (hard rule #5), which stops
at "tests pass" without asking "tests of what".

**F3 — The data layer (`drizzle`) is entirely untested.** 3 source files
including a 691-line `cli_commands.ts` (the `db:*` commands: migrate/seed/etc.)
and a 312-line `install.ts`, with **0** tests. Persistence is exactly the layer
hard rule #8 protects, and it has no automated safety net. Highest-value single
gap to close.

### MEDIUM

**F4 — No OS or Deno-version matrix; Deno version floats.** CI is
`ubuntu-latest` + `deno-version: v2.x`. The framework compiles to standalone
binaries and targets Deno Deploy; KV, session, filesystem and listener behavior
differ across macOS/Windows/Linux and across Deno point releases. A floating
`v2.x` also makes CI non-reproducible — a Deno release can turn CI red with no
repo change.

**F5 — Thin coverage on security-relevant and public-facing packages.**
`auth-provider` (11/1, decides who a user is), `openapi` (7/1, emits a public
contract document), `deprecation-contracts` (9/1), `devtools` (42/6, dev-only so
lower risk), and `ui` (91/17, the 90-component view layer). Regressions here
surface late and in consumer apps.

**F6 — No public-surface / re-export contract tests.** `@lockness/hono` is the
pinned re-export layer that hard rule #1 depends on (22 files, 0 tests). A
dropped, renamed, or type-changed re-export on a Hono version bump would not be
caught until a downstream consumer breaks. `@lockness/core` re-exports the same
surface with no export-shape assertion. A cheap snapshot/contract test would
guard the framework's central compatibility promise.

**F7 — Documented test infrastructure is under-used and not centralized.**
`docs/testing.md` mandates FakeTime (used in only 9 files) and points at one
storage mock. There is no shared `@lockness/testing` support surface: no shared
HTTP test client (18 files hand-roll it), no common in-memory fakes, no spy/stub
convention (`@std/testing/mock` is unused). The standard exists on paper but is
not made easy to follow.

### LOW

**F8 — Resource/op-leak sanitizers disabled in key tests → flaky-leak risk.**
`sanitizeResources: false` / `sanitizeOps: false` in `core/tests/kernel.test.ts`
and `storage/tests/cloud.test.ts` suppress Deno's leak detection around servers
and handles. KV/listener-heavy suites (`sse`, `session` deno-kv,
`cache/tests/shutdown` which is `gc`-gated) are classic flake sources. CI runs
no `--trace-leaks` and no retry/flake report.

**F9 — Inconsistent test-file naming defeats tooling and the doc.** Three
packages use `_test.ts` against a `.test.ts` mandate. `deno test` picks up both,
so it is not a correctness bug — but it breaks grep/glob-based coverage
accounting (it hid `vite`/`markdown` coverage in prior counts) and contradicts
`docs/testing.md`.

**F10 — Coverage/perf scope and speed are unmeasured.** `test:coverage` covers
`packages/` only (not `app/`), produces no per-package breakdown, and the
documented "<30s full suite" target is asserted nowhere in CI. No
parallelism/timing signal to catch a slow-test regression.

## Proposed backlog

Epics with imperative sub-task titles, one-line rationale, and size (S/M/L).
Every item respects the hard rules: JSR-only specifiers, no `any` in exported
test helpers, JSDoc on any exported support API, and each lands green through
the pre-completion gate.

### Epic A — Measure and gate coverage (addresses F2, F10)

- **Add a coverage job to `test.yml`** — run `deno task test:coverage`, upload
  the lcov artifact, surface a summary. Makes coverage visible before any gate.
  `M`
- **Extend `test:coverage` to include `app/` and emit a per-package summary** —
  the template app and each package get their own number, not one repo blob. `S`
- **Introduce a ratcheting per-package coverage floor** — check current lcov
  against a committed `coverage-thresholds.json`; fail if a package drops below
  its recorded floor. Ratchet up, never down; ties the gate to "tests of what",
  per hard rule #5. `M`
- **Publish a coverage badge / PR comment** — reviewers see the delta on every
  PR. `S`

### Epic B — Fill the highest-value coverage gaps (addresses F3, F5)

- **Test `@lockness/drizzle` `db:*` command surface and `install.ts`** — the
  untested data layer; use an in-memory/fake connection so it stays hermetic.
  `L`
- **Test `@lockness/auth-provider` (base + drizzle + kysely providers)** —
  identity resolution is security-relevant and at 11/1. `M`
- **Test `@lockness/openapi` document generation against route-metadata
  fixtures** — the emitted document is a public contract. `M`
- **Raise `@lockness/ui` component coverage on interactive/stateful components**
  — start with the components carrying logic (Modal, Tabs, Accordion,
  Pagination, Table). `L`
- **Add smoke tests for `@lockness/deprecation-contracts` raise/collect/render**
  — `S`

### Epic C — Harden CI topology (addresses F1, F4)

- **Add a `push` trigger to `test.yml` for `main`/`develop`** — close the
  direct-push hole so server-side checks always run, not only on PRs. `S`
- **Add an OS matrix (ubuntu / macOS / windows) to the test job** — catch
  KV/fs/listener platform divergence before binary/Deploy users hit it. `M`
- **Add a Deno-version matrix and pin a floor (e.g. current stable + `canary`)**
  — replace floating `v2.x` so CI is reproducible and forward-breaks are caught
  deliberately. `S`
- **Run the suite with `--trace-leaks` in a dedicated CI lane** — surface the
  leaks currently masked by disabled sanitizers (F8) without blocking the fast
  lane. `S`
- **Require the coverage + matrix jobs in branch protection** — make the gate
  binding. `S`

### Epic D — Test-quality standards & shared harness (addresses F6, F7, F8, F9)

- **Write a testing conventions doc / expand `docs/testing.md`** — codify naming
  (`.test.ts`), FakeTime, sanitizer policy, mock policy, and the HTTP client
  helper. `S`
- **Create a shared `@lockness/testing` support surface** — one home for the
  HTTP test client (wrapping `app.request`), common in-memory fakes, and
  FakeTime helpers; JSR-declared, JSDoc'd, no `any`. `M`
- **Add re-export contract/snapshot tests for `@lockness/hono` and
  `@lockness/core`** — assert the exported surface so a Hono bump that
  drops/renames an export fails CI, not a consumer (guards hard rule #1). `M`
- **Rename `_test.ts` files to `.test.ts` in `vite`, `markdown`, `container`** —
  one convention so glob-based tooling and the doc agree. `S`
- **Re-enable sanitizers where feasible and document each remaining opt-out
  inline** — every `sanitizeResources:false` carries a one-line reason or gets
  fixed. `M`
