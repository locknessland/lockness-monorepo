## High

### H1 — Stack traces and internals leak to clients by default (fail-open environment gate)

`packages/core/exceptions/default_view.tsx:342` — the default 500 handler sets
`showDetails = isDevelopment()`, and `isDevelopment()`
(`packages/contract/environment.ts:81`) returns `true` whenever neither
`DENO_ENV` nor `APP_ENV` is set, **and** on a `NotCapable` read — i.e. a
`deno compile` binary launched without `--allow-env` (a documented deployment
path). In those cases the server renders `error.message` and full `error.stack`
into the 500 page for every unhandled error. **Framework-default-insecure**:
this is the shipped handler every consumer inherits, and the framework's own
`devtools/gate.ts` explicitly warns that "a plain `isDevelopment()` check fails
open" and switched to `isExplicitlyDevelopment()` — the error handler never got
the same treatment. Information disclosure (file paths, framework internals, and
any query/data fragments carried in exception messages). OWASP A09/A10:2025,
ASVS V16.5.1.

**Fix sketch:** gate detail on an explicit development signal that fails closed
— replace `isDevelopment()` here with `isExplicitlyDevelopment()`, or invert to
`!isProduction()` only behind an explicit opt-in. The default for an
unknown/unset environment must be "hide details," matching what the devtools
gate already does. Pair the redacted client message with a correlation id logged
server-side.

### H2 — Path traversal in the local storage driver (arbitrary read/write/delete outside root)

`packages/storage/mod.ts:133-135` — `LocalStorageDriver.resolvePath()` returns
`join(this.config.root!, path)` with no normalization-plus-containment check.
`@std/path`'s `join` collapses `..` segments but does not prevent the result
escaping above `root` (`join('storage','../../etc/passwd')` → `../etc/passwd`).
Because this is a general file-storage abstraction whose entire purpose is to be
handed a filename, a consumer that passes a user-influenced `path` to
`get`/`getBytes`/`getStream` (arbitrary read), `put`/`putFile`/`copy`/`move`
(arbitrary write — overwriting `app/kernel.tsx` or a boot file is a path to
RCE), or `delete` (arbitrary delete) inherits traversal.
**Framework-default-insecure**: the abstraction offers no safe mode and no
guard. OWASP A05:2025, ASVS V5.

**Fix sketch:** in `resolvePath`, resolve both the root and the joined target to
absolute paths and reject when the target is not contained within the resolved
root (compare `Deno.realPathSync`/normalized prefixes, guarding the
not-yet-existing-file case). Prefer accepting opaque keys mapped server-side
over raw paths. Apply the guard once in `resolvePath` so every operation
inherits it, and also validate on the `destination` side of `copy`/`move`.

## Medium

### M1 — Session cookie ships `secure: false` by default with no production auto-hardening

`packages/session/config.ts:26` — `defaultConfig` sets `secure: false` (with
`httpOnly: true`, `sameSite: 'Lax'`), and `configureSession` merges consumer
overrides without ever deriving `secure` from the environment. The sealed cookie
**is** the session (stateless), so a cookie transmitted over plaintext HTTP and
captured can be replayed to hijack the session even though its contents are
AES-GCM-encrypted and unforgeable. **Framework-default-insecure**. Compensating
controls lower it from High: `SameSite=Lax` + `HttpOnly` are on by default, and
the payload is authenticated-encrypted. OWASP A02:2025, ASVS V7.

**Fix sketch:** default `secure` to `true`, or derive it from `isProduction()`
so it is on unless an explicit development signal is present (fail-closed), and
document the single localhost-dev override.

### M2 — Default password hashing is PBKDF2-SHA256 at 100k iterations (below current guidance)

`packages/auth/password.ts:27-32` — the built-in hasher defaults to
PBKDF2-HMAC-SHA256 at 100,000 iterations. PBKDF2 is acceptable and the verify
path is correctly constant-time, but 100k is roughly 6× below current OWASP
guidance (~600,000 for PBKDF2-SHA256) and PBKDF2-SHA256 is markedly more
GPU/ASIC-friendly than Argon2id/scrypt/bcrypt. **Framework-default**: a database
leak is cheaper to crack than it should be. OWASP A04/A07:2025, ASVS V6.2.

**Fix sketch:** raise the default iteration count to current OWASP guidance for
the chosen PRF, and/or offer Argon2id as the default with PBKDF2 as a fallback.
Keep parameters configurable and embed them in the stored hash so they can be
raised without breaking existing hashes.

### M3 — OAuth callback helper performs no `state` (CSRF) verification

`packages/socialite/mod.ts:194-209` — `BaseOAuth2Driver.user(c)`, the documented
callback entry point, reads `code` from the query and exchanges it with **no
verification of the `state` parameter**. The framework exposes `generateState()`
(`mod.ts:450`) but leaves both storing and checking state to the consumer, and
the ergonomic path validates nothing; there is also no PKCE. A consumer
following the happy path is exposed to OAuth login-CSRF.
**Framework-default-insecure** (insecure design of the convenient path). OWASP
A01/A07:2025, ASVS V10.

**Fix sketch:** have `user(c)` accept the expected state (e.g. from the session)
and reject the callback when the query `state` is absent or mismatched, failing
closed; generate and persist state inside `redirect()` rather than as an
optional argument. Document and support PKCE for public clients.

## Low

- **L1 — CI actions pinned by mutable major tag, not commit digest.**
  `.github/workflows/test.yml` and `publish.yml` reference `actions/checkout@v4`
  and `denoland/setup-deno@v2` by tag. Blast radius is contained: `publish.yml`
  triggers only on `release: published` (trusted), uses OIDC with
  `contents: read` + `id-token: write`; `test.yml` uses `pull_request` (not
  `pull_request_target`). Pin by commit SHA to close the residual supply-chain
  gap.

## Out of scope

- **Git-history secret scan (not exhaustively run).** Working tree contains no
  committed live secrets; `.env.exemple` ships an empty `APP_KEY` and a
  `postgres:postgres@localhost` placeholder DSN. Recommend a one-time
  `gitleaks`/`trufflehog` history sweep, wired into CI.
- **Dependency CVE triage, npm-specifier pinning, licence currency.**
  `deno.lock` is committed with integrity hashes; per-dependency advisory triage
  belongs to `dependency-expert`. Not assessed here.
- **CSRF middleware default.** Core does not enable a CSRF-token middleware by
  default, but the session default `SameSite=Lax` provides the baseline defence
  and `@lockness/hono` re-exports Hono's `csrf()`. Noted for completeness.
- **CLI `make:*` / seeder file writers** and **`core/http/static.ts`**
  (delegates to Hono `serveStatic`, which normalizes/rejects `..`): operate on
  trusted CLI arguments or a hardened upstream primitive, not a runtime attacker
  surface. No finding.
- **`mail`, `queue`, `cache`, `validator`, `sse`, `inertia`** were not opened
  this session; no verdict asserted. Storage upload content/size validation is
  genuinely consumer-side in this framework (no shipped validator), noted
  alongside H2.

## Proposed backlog

**Epic: Harden framework security defaults (fail-closed by default)** —
Lockness's cryptographic core (cookie sealing, APP_KEY contract) is strong, but
several shipped defaults fail _open_: error detail, cookie `secure`, KDF
strength, and the OAuth callback. This epic makes the insecure-by-default
surfaces fail closed so consumers inherit safe behaviour without opt-in.

- **Gate 500 error detail on an explicit dev signal** (H1) — **S**
- **Add path containment to `LocalStorageDriver.resolvePath`** (H2) — **M**
- **Default session cookie `secure` to true / derive from environment** (M1) —
  **S**
- **Raise default KDF strength (PBKDF2 iterations to OWASP guidance and/or
  Argon2id default)** (M2) — **M**
- **Enforce OAuth `state` (and support PKCE) in `socialite().user()`** (M3) —
  **M**
- **Pin CI actions by commit SHA** (L1) — **S**
- **One-time git-history secret sweep + CI secret scanner** — **S**
