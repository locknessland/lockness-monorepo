# `@lockness/search` — agent brief

A Scout-style full-text search abstraction over a pluggable engine, with a
memory tokenised inverted-index driver as the reference engine. Pure logic — no
workspace deps (`allow: []`).

## Invariants

- **The dependency contract below is binding.** `allow: []`; nothing imports
  `search`.
- **The query is tokenised as data and is NEVER compiled into or used as a
  regular expression** (no ReDoS, security S7). The tokeniser is **one shared
  linear function** used by both index and query — a query can never mismatch
  its own index.
- **Bounded** — query length, token count per document/query are capped.
- **Indexing is explicit; index-sync is the app's responsibility** — there is no
  ORM hook, so the app's repository calls `index()`/`delete()` on save/delete; a
  `reindex` affordance rebuilds an index.
- **Re-indexing an id replaces it** (no duplicates); `delete` removes it.
- **No `any` in exported signatures; JSDoc on every export.**

## Pitfalls

- Never "optimise" the query into `new RegExp(query)` — it must stay a tokenised
  literal match (ReDoS).
- The index drifts if the app forgets to call `index()`/`delete()` on a
  write/delete — that sync is the app's job (no ORM lifecycle exists).
- External engines (Meilisearch/Typesense) are a scoped follow-up; the memory
  driver is the reference engine.
