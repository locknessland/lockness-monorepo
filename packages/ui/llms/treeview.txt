# TreeView Component - @lockness/ui

A hierarchical tree structure component for displaying nested data with expand/collapse functionality, keyboard navigation, and full accessibility support.

## Features

- ✅ Full ARIA accessibility support (role="tree", role="treeitem", aria-expanded, aria-selected)
- ✅ Keyboard navigation (Arrow keys, Enter, Space)
- ✅ Expand/collapse branches with smooth animations
- ✅ Selectable items with visual feedback
- ✅ Custom icons support
- ✅ Two API styles: Declarative (JSX) and Data-driven (items prop)
- ✅ Zero external dependencies (pure CSS/JS)
- ✅ Full Tailwind CSS integration
- ✅ Unpoly-compatible for fragment updates

## Installation

```bash
# Add component via CLI (recommended)
deno run -A jsr:@lockness/ui add treeview

# Or use directly from package
import { TreeView, TreeViewItem } from '@lockness/ui/components'
```

## Basic Usage

### Declarative API (JSX Children)

```tsx
import { TreeView, TreeViewItem } from '@lockness/ui/components'

<TreeView>
  <TreeViewItem label="Parent" hasChildren defaultExpanded>
    <TreeViewItem label="Child 1" />
    <TreeViewItem label="Child 2" />
  </TreeViewItem>
  <TreeViewItem label="Another Parent" />
</TreeView>
```

### Data-Driven API (Items Prop)

```tsx
import { TreeView } from '@lockness/ui/components'
import type { TreeViewDataItem } from '@lockness/ui/components'

const data: TreeViewDataItem[] = [
  {
    id: '1',
    label: 'Parent',
    defaultExpanded: true,
    children: [
      { id: '1-1', label: 'Child 1' },
      { id: '1-2', label: 'Child 2' }
    ]
  },
  { id: '2', label: 'Another Parent' }
]

<TreeView items={data} />
```

## Components

### TreeView (Root Container)

Main tree container with role="tree" for accessibility.

**Props:**
- `children?: unknown` - TreeViewItem components (declarative API)
- `items?: TreeViewDataItem[]` - Data structure (data-driven API)
- `class?: string` - Additional CSS classes

### TreeViewItem (Node)

Individual tree node that can be a branch (with children) or leaf.

**Props:**
- `label: string` - Display text (required)
- `id?: string` - Unique identifier
- `hasChildren?: boolean` - Whether item has nested children
- `defaultExpanded?: boolean` - Initial expanded state
- `selectable?: boolean` - Whether item can be selected
- `defaultSelected?: boolean` - Initial selected state
- `icon?: unknown` - Optional icon element
- `children?: unknown` - Nested TreeViewItem components
- `class?: string` - Additional CSS classes

### TreeViewTrigger

Expand/collapse button (auto-rendered for branches).

**Props:**
- `icon?: unknown` - Custom trigger icon (default: chevron)
- `class?: string` - Additional CSS classes

### TreeViewIcon

Icon displayed before item label.

**Props:**
- `children?: unknown` - Icon content
- `class?: string` - Additional CSS classes

### TreeViewLabel

Label text for tree item.

**Props:**
- `children?: unknown` - Label content
- `class?: string` - Additional CSS classes

### TreeViewContent

Container for nested items (auto-rendered).

**Props:**
- `children?: unknown` - Nested content
- `class?: string` - Additional CSS classes

### TreeViewScript

Client-side JavaScript for interactivity (auto-included).

## Keyboard Navigation

| Key | Action |
|-----|--------|
| `→` (Right Arrow) | Expand branch / Move to first child if expanded |
| `←` (Left Arrow) | Collapse branch / Move to parent if collapsed |
| `↓` (Down Arrow) | Move to next visible item |
| `↑` (Up Arrow) | Move to previous visible item |
| `Enter` / `Space` | Select item (if selectable) |

## Accessibility

The TreeView component follows WAI-ARIA tree pattern:

- **role="tree"** on root container
- **role="treeitem"** on each item
- **role="group"** on nested item containers
- **aria-expanded** on branch items (true/false)
- **aria-selected** on selectable items (true/false)
- **Keyboard navigation** fully supported
- **Focus management** for screen readers

## Best Practices

1. **Use unique IDs** for data-driven trees to ensure proper state management
2. **Provide meaningful labels** for screen reader users
3. **Use icons consistently** across similar item types
4. **Set defaultExpanded** for important branches users need to see
5. **Keep tree depth reasonable** (max 4-5 levels) for usability
6. **Test keyboard navigation** to ensure all items are reachable
