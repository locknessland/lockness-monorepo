# `@lockness/features` — agent brief

Feature flags: per-scope resolution, deterministic percentage rollout, and a
pluggable override store (memory default). Pure logic — no workspace deps
(`allow: []`).

## Invariants

- **The dependency contract below is binding.** `allow: []` — pure logic, no
  workspace imports. Nothing imports `features`.
- **Resolution order is one home** (`features.ts active()`): override →
  definition (boolean/percentage/resolver) → default **off**.
- **Fail-closed** — a throwing resolver or an erroring driver resolves to
  `false`, never propagates, never fails open. Unknown flag → off.
- **Rollout is deterministic per scope** — a stable hash of `(flag, scopeKey)`,
  never `Math.random()`; it is **not** a security boundary and never a token.
- **Scope is app-supplied and must be a server-verified identity** for a flag
  that gates access/entitlement. Feature flags are a rollout/config mechanism,
  **not** an authorization boundary.
- **No `any` in exported signatures; JSDoc on every export.**

## Pitfalls

- Never resolve a security-gating flag against an attacker-controllable scope (a
  raw header/cookie) — the scope must be a verified identity.
- Nothing imports `features` — keep it a pure sink.
